## site.md

Accepted: SI1's budget table as pass or fail for the spike; SI2, SI3 (a section "Where this file overrides the
research"), SI5 to SI8, SI10 to SI25. Decided:

- **Pictures (SI4, owner question 3)**: the docs repository commits the **published** files and the recipes, not
  the originals. Renders publish as AVIF, crops and UI pictures as lossless WebP (`publish: lossy | lossless` per
  recipe); crops are never resampled; published files have content-hash names. Each recipe's stamp records the
  SHA-256 of the PNG original, so a retake is detected without storing it. PNG originals of one book version go
  into one archive attached to the docs repository's release (at most 1 GB).
- **Versions (SI9)**: the design is written down (`DOCS_ROOT`, archived versions rebuilt from tags, reserved
  `v[0-9]*` slugs) and only the reservation is implemented now; one version is built.
- **The spike decides its own questions**: where the spike's working implementation and this plan differ in a
  name or a version, the plan follows the spike unless a ruling says otherwise; the spike's report is read
  before site.md is final, so mark such places "(spike)".
- `DOCS_SITE` has no real value yet (owner question): the default build uses a placeholder origin and the
  release build fails without one.

## pipelines.md

Accepted: PI2 to PI13, PI15 to PI34. Decided:

- **The engine at the pin (PI1, blocker)**: one separate clone of the engine at the pin
  (`G:/GameEngineAI/.worktrees/docs-pin`), built **once** in Release by one agent with limited parallelism, at a
  time the planner chooses; tools take `--engine` (read with `git cat-file --batch`) and `--build`. Editors run
  `--no-gpu`, one at a time, under `Tools/PerfLock.py`, with a private session directory, and every tool checks
  `engineCommit`. No docs agent builds anything else or touches a worktree of the engine's work. So tutorials
  without rendering get their stamps in phase A, and reference dumps exist in phase A.
- **Excerpt fences (PI6)**: attributes owned by the book: `src="engine:<path>"` (also `vendor:<lib>/`, `book:`),
  `lines="A-B"` (file lines at the pin, written by the tool), `symbol="..."` (the anchor that finds the lines
  again after a pin move), and marks in file line numbers. If the spike's `tools/excerpts.py` already works
  with other names, keep the spike's names and say so.
- **Engine additions (PI14, owner question 5)**: tiers 1 and 2 land on the engine's `main` after 0.8.0 through
  CI like any change and ship as **v0.8.1**; the book's final pin is v0.8.1. Tier 3 only where a figure cannot be
  made with a debug view.
- **"Before" pictures (owner question 9)**: from the engine repository's own committed look-dev baselines at
  older tags, named with their tag.
- UI steps (PI10, owner question 8): checked by the names lint and, in phase B, by whole-editor pictures. No
  agent controls the owner's screen. The owner is invited to walk one tutorial by hand; the book does not wait
  for it.
