This part explains how the editor draws its interface and checks it by tests. It starts with the idea that the code describes the interface again every frame, then traces one frame to the screen. Scale, fonts, colors and the widget kit follow, and the shell that owns the panels is the first turning point. Next come the panels you use every day, the status bar, the dialogs, the settings windows and the instrument panels. At the end you test an interface without a screen and add a panel, so you can change any panel of the editor.
